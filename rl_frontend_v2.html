Project Idea

During federated learning, the clients train the model using their data and pass the gradients to the server. The curious server may then use these gradients to reconstruct the private data (the process is called gradient inversion attack).

The RL agent determines in each iteration which clients participate and the batch size they use. It has to trade-off between the accuracy of the model, training time, energy consumption, and privacy risk.

The issue is that the agent does not have knowledge about the true privacy risk; it only has the prediction of the privacy risk using a model built based on historical data. When the behavior of the agent changes, the prediction can become inaccurate. That is why we use uncertainty and several attacks to validate the prediction.

Research Questions

RQ1: Does the risk prediction underestimate the real risk when the scheduler changes its behaviour?
RQ2: Can uncertainty help to find these mistakes and make safer decisions?
RQ3: Do a small number of real audits improve the predictions and the scheduling?

What happens in one round

1. Observenetwork, accuracy, budget, predicted risk
2. Chooseclients + batch size
3. Trainclients compute gradients
4. Uploadserver sees gradients (risk!)
5. Auditsometimes we run a real attack to check the risk

Problem Formulation (MDP)

State

  • Network speed and load of each client
  • Validation loss and accuracy
  • Time used and samples left in the budget
  • Which clients took part in recent rounds
  • Predicted risk and uncertainty for every action

Reward

reward = accuracy gain - α × time - β × energy - λ × (increase in average risk)

The risk used is mean + κ × uncertainty. When κ = 0 we use only the prediction, when κ = 1 we are more careful (conservative).

Episode

30 rounds, the first 12 are warm-up rounds where every action is tried once. The episode can end early if the sample budget (3000) runs out.
