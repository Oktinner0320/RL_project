# 研究协议：动态调度下风险代理的可靠性

## 研究问题与可证伪结论

核心问题是：调度策略改变客户端参与、批量大小和训练轨迹后，基于既有轨迹训练的风险代理是否发生策略诱导的分布偏移，进而系统性低估真实梯度反演风险？在有限攻击预算下，不确定性驱动审计和分阶段校准能否减少低估，并改善调度决策的可靠性？

应用目标是在相同实验约束下，联合调度客户端集合与批量大小，比较模型效用、时间、能量和经验泄露风险。研究结果不预设“动态调度一定造成偏移”“主动审计一定有效”或“DQN/PPO 必然优于简单基线”。没有显著收益时，报告适用条件和失败原因。

风险是指定攻击者、数据和攻击预算下的经验重构能力，不是差分隐私保证，也不是所有可能攻击的风险上界。代理输出的不确定性需通过独立数据检验，不能仅凭模型返回一个数值就宣称校准成立。

## 数据、联邦更新与威胁模型

使用 UCI Adult 官方训练/测试文件。验证集从官方训练数据按类别留出；编码词表、数值均值和标准差只从最终训练记录拟合。保存下载文件散列、训练/验证索引和客户端划分。IID 与 label-skew 划分由 Notebook 指定，空客户端或批量超过可用记录时明确报错，不偷偷重抽一个更有利的数据分配。

一个逻辑训练任务模拟三个客户端。每个选中客户端从自己的训练记录中无放回抽取本轮 batch；跨轮允许重复。各客户端使用同一个更新前模型计算平均批梯度，服务器加权聚合后执行一次全局更新，即本项目的 FedSGD 语义。PyTorch 模型和更新算法由研究者实现。

威胁模型允许攻击者看到**聚合前的单客户端梯度**、更新前模型参数与该源模型的公开构建配置、该批已知标签、批量大小和公开编码信息。权重形状无法还原激活函数等设置，因此 `model_config` 必须随源上传保存，不能从当前审计配置猜测。该模型对应能观察单客户端上传的攻击者，不对应只有安全聚合结果可见的攻击者。原始记录、训练行号和参考路径仅由可信评价端持有。

每个上传记录以独立 ID 对齐攻击输入和参考真值。攻击输入的张量保存为 detached CPU 副本；参考记录另存。反演函数执行完成后，评价端才加载参考真值。审计只处理实际发生的上传，不生成未选客户端或未执行动作的反事实梯度。

## 状态、动作、奖励与预算

动作是 Notebook 中客户端集合与 batch 候选值的笛卡尔积，客户端编号从零开始。状态由当前上下行带宽/负载、验证进度、各客户端参与次数与采样覆盖、候选动作收益/时间/能量/风险/不确定性和风险可用标志构成。它不包含真实梯度、攻击重构标签或未来资源。

候选效用是已执行动作对应验证损失下降的 EMA；初始先验、衰减与共享预热动作均来自 Notebook。只更新执行过的动作，不把未执行动作写成真实收益。所有方法共享状态构造、动作空间、初始模型条件与同一规则的预热成本。

单客户端风险先计算 `clip(mean + kappa * uncertainty, 0, 1)`，再对选中客户端平均。`kappa` 对应 Notebook 的 `uncertainty_weight`；平均风险用于奖励，最大客户端风险单独记录。不能先平均再截断，也不能在奖励中重复惩罚同一不确定性项。

一步奖励为本轮验证损失下降，减去归一化时间、能量和预测风险惩罚。所有权重、归一化尺度和预算仅在 Notebook 中指定。真实攻击结果不即时回灌本轮奖励；它们通过离线审计与后续风险版本更新影响新阶段。

资源轨迹按绝对模拟时槽与种子确定。每轮开始读取当前时槽资源，轮内保持该速率，是离散近似；候选评估不预读未来。轮时延为最慢客户端的下载、计算、上传耗时之和再加聚合耗时。通信量按模型字节计，不随 batch 简单倍增；能量按通信/计算功率与时间及服务器聚合计量。

时间预算、累计处理样本预算或验证目标触发 `terminated`，最大轮数限制触发 `truncated`。完整训练轮完成后才结算，因此可能整轮超出预算；不能把超出的计算和上传删掉。分别报告总处理样本、唯一记录、各客户端曝光、累计字节、时间和能量。

## Bootstrap、校准与公平比较

初始风险模型尚不存在时使用显式不可用模式：观察带 `risk_available=0`，数值占位不代表真实零风险，上传清单中预测为 `None`，风险惩罚权重必须为零。先由固定或轮询策略采集上传，再做周期或随机审计。主动审计需要真实风险预测与不确定性，不能用于伪造初始标签。

风险模型的训练/校准按**完整运行**分组，避免同一轨迹的相邻上传跨入训练和验证。风险估计器拟合时只能使用标记为训练运行的审计标签。最终评价使用独立测试运行；测试审计标签不能再用于调参或风险拟合。数据集本身的 train/validation/test 划分与风险轨迹的训练/测试划分是两层不同隔离。

每个 RL 阶段冻结一个风险版本；阶段结束后利用追加审计校准新版本。版本切换时如何保留策略权重、清空旧 replay 并重新开始训练轨迹，由用户算法明确执行。相同版本下恢复则保留完整训练状态和环境状态，不重新抽取初始条件。

固定、轮询、时延贪心、风险贪心与 DQN/PPO 使用同一可见状态和预算口径。审计方法在同一实际上传池上比较：周期方法按明确间隔取样，随机方法按种子排序，主动方法按不确定性与决策接近程度排序。比较时同时报告攻击次数和真实攻击时间；相同次数不等于相同算力成本。

审计受调用数与攻击时间双预算约束。先对实际上传执行 `benchmark_attack`，按 batch 测量攻击耗时，并在 Notebook 中明确传入对应 benchmark 运行。开始下一次攻击前使用该耗时估计判断剩余预算，攻击完成后记录真实耗时；单次攻击超出预算则整次计入并停止，报告 `budget_overrun_seconds`。GPU 工作完成后同步计时。该限制不是 Modal 账单硬上限。

最终独立审计面板按动作和客户端组织实际上传。报告面板覆盖了哪些动作/客户端，以及哪些没有覆盖；不要把观察到的覆盖率当作全部候选动作的因果反事实评价。

## 指标与结果解释

重构先在一个 batch 内进行 Hungarian 匹配，再按 Adult 的原始字段评价。类别字段要求精确一致，数值字段允许 Notebook 预声明的训练集标准差倍数误差。指标在解码后的原字段上计算，不能用大量 one-hot 零位置抬高恢复率。

| 维度 | 报告内容 |
|---|---|
| 梯度泄露 | 原字段平均恢复率、数值/类别恢复率、整条记录全部字段恢复率 `EMR` |
| 攻击有效性 | 与均匀随机重构、训练边际先验重构比较；攻击方法、初始化、重启和真实耗时 |
| 代理可靠性 | 预测误差、低估幅度、低估频率、真实风险超阈值频率；明确是否评价均值或不确定性修正后风险 |
| 最坏情况 | 最坏客户端的预测与已审计实际风险；覆盖不足时明确样本限制 |
| 学习效用 | 验证轨迹和仅在最终阶段读取的测试集指标 |
| 资源与审计 | 时间、能量、字节、累计/唯一样本、客户端曝光、攻击次数与时间、预算超出量 |

这里的 `EMR` 使用预声明的数值容差，并非所有浮点值逐位完全相等。阈值和容差必须在 Notebook 中固定后再评价。随机与边际先验只作为评价端基线，不是算法缺失时的替代攻击。

实验应保存每个 seed 的独立结果，并在相同条件下做配对比较；均值、离散程度和失败案例都要保留。研究总结 PDF 建议 DQN/PPO 与多种子评估，其中“五个 seed”属于研究建议，不是课程文件规定的强制条款；实际运行集合由 Notebook 决定。

本协议规定了应收集和解释的证据，不表示这些实验已经运行。算法空缺、云端验证和课程报告按 [TASKS.md](TASKS.md) 分别追踪。
