# RL cloud–edge interaction lab

Read-only strict TypeScript + Vite + ECharts interactive lab for existing `results_visualization_v1` snapshots. All implementation lives in `frontend/`; no image assets, exporters, experiment code or notebooks are modified. No training, cloud, artifact rewriting or acceptance calculations.

## Build

Node 22.12+ (or 24+) is recommended. From this directory:

```
npm install --no-audit --no-fund
npm run test
npm run typecheck
npm run build
```

Serve `dist/` with the existing local notebook service. The frontend requires only the built application and JSON snapshots: it does not request publication images or a figure manifest. Snapshot fetches use Vite's `BASE_URL` + `data/index.json`; only paths listed in the index are followed. Files under `public/data/` are generated by the exporter and are never fabricated by this UI. Rebuild after exporting new public data. For a subpath deployment configure Vite's base at build time.

## Single-page interaction

The presentation uses a black background with coordinated dark controls, cards, SVG nodes, charts and inspector. Main-screen copy is limited to titles, controls and concise metric labels; detailed data limitations remain available in the current-round inspector.

The local collaboration canvas uses tsParticles Engine + Basic (4.4.0), loaded on demand, over persistent SVG light cores/rings. A custom updater follows the same deterministic coordinates as the SVG paths: scoring → download → local computation → recorded uploads → aggregation → feedback. No random topology, full-screen background or mouse attraction. Motion is a one-second mechanism illustration, not measured event timing; particle counts do not encode batch, samples, bytes or risk. Upload motion requires matching upload metadata; missing mappings and large (>8-client) topologies remain static. The visual budgets are at most 96 particles/60 FPS on desktop and 48 particles/30 FPS on narrow screens, not universal performance guarantees.

The motion control, reduced-motion preference, hidden tab and off-screen canvas pause the engine; disabling motion leaves the complete SVG and interactions. Frame changes update the scene without recreating the container; run/episode/snapshot replacement destroys it, including asynchronous initialization. A load failure leaves the static SVG usable. Hover/focus on an action links the corresponding node rings; candidate clicks pause playback and only add amber dashed outlines, never candidate particle flows or computed outcomes. Resuming actual playback clears the candidate overlay immediately.

- The only screen is **云边交互台**. There is no sidebar, page navigation, learning view, method/checkpoint comparison, calibration/report panel, experiment register or publication gallery. Removed and unknown `page` parameters resolve to the same lab; obsolete comparison/learning URL parameters are discarded. Existing paper assets and experiment code remain untouched outside the frontend.
- **Cloud–edge lab:** State → Agent → joint Action → cloud–edge Environment → Reward. A generated, keyboard-operable SVG shows the actual clients, bidirectional communication and aggregation, not a PNG with hotspots. The timeline, action matrix, top-three ranking, outcome curves and current-round inspector share one selected frame. Clicking a curve point changes the frame; the slider provides a keyboard alternative.
- **Candidate exploration:** click an explicit client-set × batch action. Actual execution stays solid/green; preview is dashed/amber. Only the recorded score for that state is compared, with Q values, probabilities and heuristic scores named separately. Preview never mutates experimental records or calculates counterfactual accuracy, cost or risk. A round change clears the preview.
- **State and evidence boundaries:** full historical observations are not exported. Unique adjacent-round feedback is shown only as a reference, not as the agent's complete input. Missing mappings, scores, metrics and audits remain missing. Warmup is explicit. Reward uses the recorded total without reconstructed components. Per-round bytes are totals, never divided across clients. Uploads join numeric episode/round with `round_index` normalization; missing keys, conflicting aliases and duplicate metric/decision keys are not silently resolved. Audit records match exact run IDs and unique upload IDs, retain model/scope, and never imply whole-policy coverage or safety.
- Snapshot, validation run, episode/frame and candidate preview persist in the URL. Policy/run/episode and snapshot changes dispose replay timers, particle containers/observers, dialogs, chart instances and linked groups; playback is a one-second observation cadence, not actual event timing. Hiding the tab pauses record playback. Reduced-motion preferences suppress continuous particle animation. Summary-only validation data degrade explicitly rather than creating an execution trace.
- Method colors are fixed and colorblind-aware. N1/N3 use distinct blue/orange and solid/dashed styles rather than identical DQN colors.

## Limitations

No seed-derived CI, inferred acceptance, reconstructed historical state, client-level byte allocation or pooled calibration. Candidate scores require a uniquely matched decision with a known kind and explicit action IDs. The graph illustrates simulated client cooperation, not actual network timing or live device status. Schema/provenance records remain inspectable. Frontend selector, replay and particle regression tests use Node's built-in runner and live in ignored `test/`; no new test framework.

## Additional strategy playback

`public/replays/native-validation-v1.json` is a frontend-owned, read-only projection of seven existing **2026-10-08 historical validation runs**, not a replacement for exporter-owned `public/data/` snapshots. Loading appends these distinct runs in memory; method selection prefers a mapped multi-round trajectory, while the run selector still allows newer summary-only records. Both date and coverage are labeled. Historical DQN has 29 rounds; PPO, PQN, META-CS, Fixed, Time-Greedy and Risk-Greedy each have 30 (209 total). DQN and PPO retain their 17 Q-value and 18 probability vectors; the other five methods did not save vectors and show missing scores, not inferred preferences.

`node scripts/prepare-replays.mjs` regenerates this projection from the fixed local source paths without executing/importing the experiment framework, downloading artifacts, training, or changing any input. Each source file is limited to 4 MiB, each run to 1,000 metric/decision rows and 5,000 uploads, and the full projection to seven specified runs. Identity, completion, final-summary consistency, saved action mappings and upload joins are checked. Safe fields are whitelisted: no gradients, features, sample identities, packet/reference paths or model checkpoints are copied. SHA-256 checksums and project-relative source paths are included; inputs are rechecked before publication. For a sample gate, use `--sample metacs --out <approved external temporary path>` before regenerating all seven. Rebuild afterwards so the supplemental JSON is included in `dist/`.

Missing or invalid supplemental JSON leaves the original snapshot usable, with a load warning in the provenance panel. Duplicate IDs preserve original snapshot records rather than overwriting or concatenating rounds. Historical risk version, seed and phase remain separate; checkpoint steps, actual training budgets and cloud cost are not inferred. These records enable playback only and do not establish current-batch results, fair cross-batch comparisons or formal acceptance.
